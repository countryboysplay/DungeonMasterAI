# Local AI Tactical Map Generation

DungeonMasterAI uses the existing local llama.cpp/OpenAI-compatible chat endpoint to **author structured tactical-map data**. The language model does not render pixels and is never authoritative for map geometry.

## Generation pipeline

`description -> local Llama JSON -> application normalization -> deterministic validation -> optional repair -> candidate map -> user review -> campaign`

The generator returns a candidate `TacticalMap`. It does not silently add the map to `CampaignState`. The future Campaign Builder owns preview, editing, regeneration, acceptance, and campaign packaging.

## Application-owned fields

The application supplies and reasserts these values after every model response:

- map type
- theme
- asset-pack ID
- width and height
- feet per square
- deterministic seed
- fog-of-war setting
- schema version
- `sourceKind=ai_generated`

Missing object IDs are generated by the application before validation.

## Asset whitelist

The model receives a list of allowed semantic asset keys. Generated maps are rejected if they reference any other key. This prevents the model from inventing filenames or visual resources that are not installed.

The default r55 key set corresponds to the current core fantasy crypt contract, including flagstone floors, stone walls, ironbound/broken/secret doors, shallow water, rubble, pillars, altar, sarcophagus, torch, and brazier keys.

Future Campaign Builder generation should populate the whitelist from the actual selected asset pack or from a compatible semantic-key intersection across installed packs.

## Geometry contract

Generated maps must pass `TacticalMapGeometry.Validate` before they can be returned as accepted candidates. Among other checks:

- rectangles remain within bounds;
- walls are axis-aligned;
- wall endpoints remain on/inside the map boundary;
- door edges remain within bounds;
- doors should be embedded in explicit wall segments;
- dimensions and grid scale are valid;
- object IDs are unique.

r55 adds generation-specific requirements:

- at least one room/region;
- at least one player-side spawn point;
- every visual key belongs to the application-provided whitelist.

## Repair pass

The model gets at most one automatic repair attempt.

If the first candidate fails parsing or validation, the second request includes:

1. the rejected JSON;
2. deterministic validation errors;
3. the original application-owned dimensions/theme/asset set/seed;
4. the same allowed asset-key list.

If the repaired candidate is still invalid, generation fails visibly instead of accepting a broken map.

## Local model compatibility

No new AI runtime is required. `TacticalMapAiGeneratorService` uses the same `settings.LlamaServerUrl`, model name, and `/v1/chat/completions` endpoint already used by the local campaign compiler and DM client.

The current model therefore remains the planner. The deterministic map engine and asset-pack renderer remain responsible for correctness and presentation.

## Future Campaign Builder UX

A future generation form can collect:

- description
- dungeon/cave/exterior/etc. type
- theme
- map dimensions
- grid scale
- selected asset pack
- optional explicit seed
- fog-of-war preference

After generation, the Builder should show the rendered candidate plus validation warnings and actions such as Regenerate, Change Theme, Regenerate Decorations, Edit, and Add to Campaign.
